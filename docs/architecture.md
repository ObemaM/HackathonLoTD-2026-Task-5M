# Архитектура

## Поток данных

```text
ROS 2 bag / реальный лидар
        │ PointCloud2
        ▼
obstacle_detector
        │
        ├── декодирование и удаление NaN/(0,0,0)
        ├── преобразование осей в X-forward, Y-left, Z-up
        ├── voxel downsampling
        ├── захват ближней пары и последовательное сопровождение рельсов
        ├── локальная сглаженная центральная линия пути
        ├── контроль неоднозначной стрелки
        ├── изогнутый габарит 2.1 x 3.0 м
        ├── узкая маска рельсов и продольной инфраструктуры
        ├── Euclidean clustering
        ├── выбор ближайшего кандидата
        └── подтверждение на нескольких кадрах
        │
        ├── /obstacle_detector/detected
        ├── /obstacle_detector/distance_m
        ├── /obstacle_detector/processing_time_ms
        ├── /obstacle_detector/track_valid
        ├── /obstacle_detector/route_ambiguous
        ├── /obstacle_detector/debug/filtered
        ├── /obstacle_detector/debug/candidates
        └── /obstacle_detector/markers
```

## Системы координат

Внутри алгоритма используется единое соглашение:

- `X` — вперёд вдоль пути;
- `Y` — поперёк пути;
- `Z` — вверх.

Исходные bags ориентированы иначе: вперёд примерно соответствует `-Y`. Перестановка и
знаки осей задаются в YAML. Узел также публикует статический TF между исходным frame и
`train_lidar`, поэтому отладочные облака можно совмещать с исходным в RViz.

## Оценка своего пути

Низкий срез облака делится на продольные секции. Для каждого возможного поперечного
центра считается поддержка двух линий с расстоянием, равным ширине колеи. Сначала
захватывается ближайшая к лидару достоверная пара, затем она последовательно
продолжается наружу. На каждом шаге проверяется, что линия:

- начинается рядом с положением лидара нашего поезда;
- поддерживается точками с обеих сторон;
- сохраняет фактическую ширину колеи;
- не перепрыгивает резко на соседний путь;
- плавно продолжается через поворот.

Выбранные центры образуют локальную кусочно-линейную траекторию со сглаживанием. Поэтому
дальний поворот больше не заставляет единую параболу начинать изгиб слишком рано. Если
две хорошо поддержанные пары последовательно расходятся, публикуется
`route_ambiguous=true`, а коридор заканчивается перед развилкой. При недостатке
поддержанных секций публикуется `track_valid=false` и используется прямой коридор.

Маска продольной инфраструктуры работает в координатах относительно найденной линии.
Она исключает только низкие линии, наблюдаемые во многих секциях. Компактный объект
не должен попасть в эту маску.

## Что остаётся разработать

1. Калибровка rail-height параметров для `doubleT_obstacle`.
2. Банк ветвящихся временных гипотез или вход с маршрутом для выбора ветви стрелки.
3. Эталонная карта чистого проезда для оставшейся штатной инфраструктуры.
4. Range-adaptive clustering для дальних разреженных объектов.
5. Трекер с компенсацией движения поезда.
6. Генератор синтетических препятствий и автоматический benchmark.
