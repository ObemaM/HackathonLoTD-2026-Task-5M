# Архитектура

## Поток данных

```text
ROS 2 bag / реальный лидар
        │ PointCloud2
        ▼
obstacle_detector
        │
        ├── декодирование и удаление NaN/(0,0,0)
        ├── преобразование осей в X-forward, Y-left, Z-up
        ├── voxel downsampling
        ├── прямой параметризованный габарит 2.1 x 3.0 м
        ├── отсечение пола по высоте
        ├── Euclidean clustering
        └── выбор ближайшего кандидата
        │
        ├── /obstacle_detector/detected
        ├── /obstacle_detector/distance_m
        ├── /obstacle_detector/processing_time_ms
        ├── /obstacle_detector/debug/filtered
        ├── /obstacle_detector/debug/candidates
        └── /obstacle_detector/markers
```

## Системы координат

Внутри алгоритма используется единое соглашение:

- `X` — вперёд вдоль пути;
- `Y` — поперёк пути;
- `Z` — вверх.

Исходные bags ориентированы иначе: вперёд примерно соответствует `-Y`. Перестановка и
знаки осей задаются в YAML. Узел также публикует статический TF между исходным frame и
`train_lidar`, поэтому отладочные облака можно совмещать с исходным в RViz.

## Что реализовано сейчас

Текущая версия — исполняемый геометрический baseline с прямым коридором. Он нужен для
ранней end-to-end интеграции, измерения скорости и калибровки данных.

## Что остаётся разработать

1. Поиск рельсов по поперечным срезам.
2. Сглаженная центральная линия пути.
3. Изогнутый swept corridor вместо прямого параллелепипеда.
4. Более корректное удаление пола, рельсов и штатной инфраструктуры.
5. Range-adaptive clustering для дальних разреженных объектов.
6. Короткое временное подтверждение и компенсация движения.
7. Генератор синтетических препятствий и автоматический benchmark.
